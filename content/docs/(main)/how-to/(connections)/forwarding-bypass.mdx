## What this is for

Use **Player forwarding** when the target is a backend server behind a BungeeCord or Velocity proxy, and you want bots to connect to that backend directly.
The plugin sends the forwarded player data that the backend expects from its proxy.
With `SF_BYPASS` mode, it instead lets offline-mode bots through an online-mode proxy that runs the separate SoulFireBypass plugin.
Releases up to 2.10.7 call this feature **Forwarding Bypass**. The plugin ID stays `forwarding-bypass`.

Leave the plugin off for a standalone server without proxy forwarding.

| Mode | Use it when | Needs **Secret** | Uses **Player Address** |
|------|-------------|------------------|-------------------------|
| `LEGACY` (default) | The backend expects classic BungeeCord IP forwarding | No | Yes |
| `BUNGEE_GUARD` | The backend uses BungeeGuard on top of legacy forwarding | Yes | Yes |
| `MODERN` | The backend uses Velocity modern forwarding | Yes | Yes |
| `SF_BYPASS` | The proxy runs the SoulFireBypass plugin | Yes | No |

**Player Address** is the IP that the backend sees for each bot. The default is `127.0.0.1`.

The CLI flags are `--forwarding-bypass-enabled`, `--forwarding-bypass-forwarding-mode`, `--forwarding-bypass-secret`, and `--forwarding-bypass-player-address`.

<Callout type="warn">
  A backend that accepts forwarded data trusts its sender to be the proxy.
  Protect the secret. A backend port that is open to the internet with legacy forwarding lets anyone join as any player.
</Callout>

## Enable Player forwarding in SoulFire

<Steps>
  <Step>
    ### Open the project

    Open the SoulFire project that will run the bots.
  </Step>

  <Step>
    ### Enable the plugin

    Open **Plugins** and enable **Player forwarding**.
  </Step>

  <Step>
    ### Select the forwarding mode

    Open **Plugin Settings** and choose the mode that matches your proxy and backend setup.
  </Step>

  <Step>
    ### Fill in the shared values

    Set **Secret** if your mode needs one. Use the same value as the proxy and backend configuration.
    Change **Player Address** if the backend must see a specific player IP.
  </Step>

  <Step>
    ### Start a small test first

    Set the address in **Bot Settings** to the backend server. For `SF_BYPASS`, use the proxy address instead.
    Start one bot.
    Make sure that the backend accepts it before you add more bots.
  </Step>
</Steps>

## How each mode behaves

- `LEGACY` adds BungeeCord forwarding data to the handshake hostname.
- `BUNGEE_GUARD` uses the legacy format and adds the BungeeGuard token to the forwarded profile properties. Use the token configured on your network.
- `MODERN` answers Velocity's `velocity:player_info` request during login. Use the forwarding secret shared by your Velocity proxy and backends.
- `SF_BYPASS` adds a `SF_<secret>` marker to the handshake hostname. It does not imitate proxy forwarding. See the next section.

## Set up SoulFireBypass

[SoulFireBypass](https://modrinth.com/plugin/soulfirebypass) is a separate proxy plugin. Its source code is at [soulfiremc-com/SoulFireBypass](https://github.com/soulfiremc-com/SoulFireBypass).
Use it when real players must keep online-mode authentication, but SoulFire's offline-mode bots must join the same proxy.

If a handshake contains a valid `SF_<key>` marker, the plugin switches that connection to offline-mode login.
Connections without a valid key stay on the normal online-mode path.

<Callout type="warn">
  Anyone who knows a valid SoulFireBypass key can join as any player through that proxy.
  Treat the key like a password and replace it if it is exposed.
</Callout>

### Proxy-side setup

<Steps>
  <Step>
    ### Install the plugin on the proxy

    Download SoulFireBypass from [Modrinth](https://modrinth.com/plugin/soulfirebypass) and put it in your proxy's plugins folder.
    The Modrinth listing supports Velocity, BungeeCord, and Waterfall.
  </Step>

  <Step>
    ### Start the proxy once

    Start the proxy so the plugin creates its data folder and `config.yml`.
  </Step>

  <Step>
    ### Configure allowed keys

    Edit the generated `config.yml` and replace the placeholder value under `allowed-keys` with a strong secret.

    ```yml
    allowed-keys:
      - replace_this_with_a_long_random_key
    ```
  </Step>

  <Step>
    ### Restart the proxy

    Restart after saving the config so the new key is loaded.
  </Step>
</Steps>

### SoulFire-side setup

<Steps>
  <Step>
    ### Enable Player forwarding

    In SoulFire, enable the built-in **Player forwarding** plugin.
  </Step>

  <Step>
    ### Select SoulFire Bypass mode

    Open **Plugin Settings** and set **Forwarding mode** to **SoulFire Bypass** (`SF_BYPASS`).
  </Step>

  <Step>
    ### Use the same key

    Set **Secret** to the same value that you added to `allowed-keys` on the proxy.
  </Step>

  <Step>
    ### Join through the proxy entry point

    Point SoulFire at the normal proxy address, not a backend server.
  </Step>
</Steps>
