## What this is for

Use **Ping before join** when a target network rejects clients that join without a server list ping first.
Releases up to 2.10.7 call this feature **Server List Bypass**. The plugin ID stays `server-list-bypass`.

For each bot, the plugin:

1. sends a status ping, like the multiplayer server list does
2. waits a random delay
3. starts the real join

Some anti-bot systems, such as EpicGuard, expect a status ping before login.
Whether the server then accepts the join depends on its configuration.

<Callout type="info">
  Normal servers do not need this plugin. Leave it off unless the target uses an anti-bot layer.
  It does not fix dead proxies, wrong addresses, invalid accounts, or broken forwarding.
</Callout>

## Enable Ping before join

<Steps>
  <Step>
    ### Enable the plugin

    Open **Plugins** and enable **Ping before join**.
  </Step>

  <Step>
    ### Set the delay range

    Set **Min delay (seconds)** and **Max delay (seconds)**. The defaults are 1 and 3.
    Keep the defaults for the first test.
  </Step>

  <Step>
    ### Compare one bot with and without the plugin

    Join with one bot without the plugin, then with it.
    If the result does not change, the ping is not the cause. Turn the plugin off and check the other settings.
  </Step>
</Steps>

## Common failure patterns

| Symptom | Next step |
| --- | --- |
| The ping works, but the join still fails | Increase the delay a little. If the error stays the same, check proxies, [forwarding](/docs/how-to/forwarding-bypass), and the [handshake host](/docs/how-to/fake-virtual-host). |
| Joins fail with and without the plugin | The cause is elsewhere. See [Cannot connect or times out](/docs/troubleshooting/cannot-connect-or-times-out). |
| One bot joins, but larger batches fail | The server rate-limits joins, or the proxies are poor. Increase the join delay in **Bot Settings** or [check the proxies](/docs/troubleshooting/proxies). |
