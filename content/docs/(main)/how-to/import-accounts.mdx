## Before you start

- A project needs at least one account before bots can start.
- Use offline accounts only on servers that run in offline mode, sometimes called cracked servers.
- For exact file formats and defaults, see [Account formats](/docs/reference/account-formats).

<Callout type="info">
  Need more test accounts (alts)? See [Get Accounts](/get-accounts).
  If you use Ravealts, SoulFire can import purchases directly from the **Add accounts** menu.
</Callout>

## Choose the right account type

Select **Add accounts** on the **Accounts** page. The menu groups the types under **Java Edition** and **Bedrock Edition**.

| Type | Use it when |
| --- | --- |
| **Microsoft credentials** | You have a normal account with email and password |
| **Microsoft device code** | You want to sign in through a browser instead of storing credentials |
| **Microsoft refresh token** (Java only) | You already have refresh tokens and want long-lived imports |
| **Microsoft cookies** (Java only) | You want to import a browser login session |
| **Microsoft access token** (Java only) | You only have a short-lived access token |
| **Offline** | The target server accepts offline-mode accounts |

Choose the type under **Bedrock Edition** to connect to Bedrock servers.

## Generate offline accounts

Open **Accounts** and select **Generate accounts**.
Set the amount and a name format such as `TestBot_%d`.
The client replaces `%d` with a number, starting at `1`.
Review the duplicate-handling mode before generating accounts.

Check the resulting account list before starting bots.
If you press **Start** with an empty list, the client can open this dialog for you.

## Import accounts in the GUI

<Steps>
  <Step>
    ### Open the Accounts page

    Open a project and go to **Accounts**.
  </Step>

  <Step>
    ### Select the account type

    Select **Add accounts**, then choose the type that matches the data you want to import.
  </Step>

  <Step>
    ### Paste or import the account data

    Add one account per line using the format for that account type.
    For device-code flows, SoulFire prompts you to finish the login in a browser.
  </Step>

  <Step>
    ### Review the imported accounts

    Make sure that the project shows the expected accounts.
    Start one bot first. Check its login result before starting the remaining accounts.
  </Step>
</Steps>

## Import accounts in CLI mode

CLI imports use two flags:

- `--account-file` points to the file that contains the accounts.
- `--account-type` tells SoulFire how to parse that file. [Account formats](/docs/reference/account-formats#cli-values) lists the values.

```bash
java -jar SoulFireCLI.jar --account-file accounts.txt --account-type OFFLINE
```

Add the other CLI flags that your setup needs, as [CLI mode](/docs/start-here/cli-mode) shows.
For the full flag list, see [Command line flags](/docs/reference/cli-flags).

## Settings that matter most

| Setting | What it changes |
| --- | --- |
| **Shuffle accounts** | Randomizes the account order before bots join |
| **Use proxies for account auth** | Sends Microsoft authentication through your configured proxies |
| **Account import concurrency** | Controls how many account imports run at the same time. The default is 3. |
