## Before you start

- Add at least one account before starting a run. Generate offline accounts explicitly from the client dialog.
- Use offline accounts only on servers that accept them.
- For exact file formats and defaults, see [Account Formats](/docs/reference/account-formats).

<Callout type="info">
  Need sources for test accounts? See [Get Accounts](/get-accounts).
  If you use Ravealts, SoulFire can import purchases directly from the account settings dialog.
</Callout>

## Choose the right account type

| Type | Use it when |
| --- | --- |
| **Microsoft Java Credentials** | You have a normal Java account with email and password |
| **Microsoft Java Device Code** | You want to sign in through a browser instead of storing credentials |
| **Microsoft Bedrock Credentials** | You want to connect to Bedrock servers |
| **Microsoft Bedrock Device Code** | You want browser-based Bedrock sign-in |
| **Microsoft Java Refresh Token** | You already have refresh tokens and want long-lived imports |
| **Microsoft Java Cookies** | You want to import a browser login session |
| **Microsoft Java Access Token** | You only have a short-lived access token |
| **Offline** | The target server accepts offline-mode accounts |

## Generate offline accounts

Open **Account Settings** and use the offline account generation dialog.
Set the amount and a name format such as `TestBot_%d`.
The client replaces `%d` with a number, starting at `1`.
Review the duplicate-handling mode before generating accounts.

Check the resulting account list before starting bots.
If you press **Start** with an empty list, the client can open this dialog for you.
It does not turn a name format into a persistent server setting.

## Import accounts in the GUI

<Steps>
  <Step>
    ### Open the account settings

    Open an instance and go to **Account Settings**.
  </Step>

  <Step>
    ### Select the account type

    Choose the type that matches the data you want to import.
  </Step>

  <Step>
    ### Paste or import the account data

    Add one account per line using the format for that account type.
    For device-code flows, SoulFire prompts you to finish the login in a browser.
  </Step>

  <Step>
    ### Review the imported accounts

    Make sure that the instance shows the expected accounts.
    Start one bot first. Check its login result before starting the remaining accounts.
  </Step>
</Steps>

## Import accounts in CLI mode

CLI imports use two flags:

- `--account-file` points to the file that contains the accounts.
- `--account-type` tells SoulFire how to parse that file.

Add the other CLI flags that your setup needs.
For the full flag list, see [Command line flags](/docs/reference/cli-flags).

## Settings that matter most

| Setting | What it changes |
| --- | --- |
| **Shuffle accounts** | Randomizes the account order before bots join |
| **Use proxies for account auth** | Sends Microsoft authentication through your configured proxies |
| **Account import concurrency** | Controls how many account imports run at the same time |
