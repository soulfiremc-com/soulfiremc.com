## What this is for

Use **Auto login and register** when the target server asks players to type `/register` or `/login` in chat after they join.
This is how AuthMe and similar login plugins work.
Releases up to 2.10.7 call this feature **Auto Register**. The plugin ID stays `auto-register`.

The plugin reads every chat message:

- If the message contains `/register` or `/reg`, the bot sends the register command.
- Otherwise, if the message contains `/login` or `/l`, the bot sends the login command.
- The bot waits a random delay before it sends the command.

A prompt that mentions both `/register` and `/login` gets the register command.
The plugin does not help with GUI-based login or registration that does not use chat.

<Callout type="warn">
  The check looks for these strings anywhere in a message.
  A message that mentions `/lobby` or `/list` contains `/l`, so the bot sends its login command and password in reply.
  Use this plugin only on servers whose chat does not show such commands, and use a test password.
</Callout>

## Configure Auto login and register

<Steps>
  <Step>
    ### Enable the plugin

    Open **Plugins** and enable **Auto login and register**.
  </Step>

  <Step>
    ### Match the server's commands

    Set **Register Command** and **Login Command** to the syntax that the server prompt shows.
    SoulFire replaces `%password%` with the password.

    | Setting | Default |
    | --- | --- |
    | **Register Command** | `/register %password% %password%` |
    | **Login Command** | `/login %password%` |
  </Step>

  <Step>
    ### Set the password

    Set **Password Format** to the password that the bots use.
    The default is `SoulFire`. Every bot in the project uses the same password.
  </Step>

  <Step>
    ### Set the delay

    Set the minimum and maximum delay in milliseconds. The defaults are 0 and 1000.
    Increase the delay only if the server rejects commands that arrive too fast.
  </Step>

  <Step>
    ### Test with one bot

    Start one bot and check that the server accepts its register or login command.
    Then start more bots.
  </Step>
</Steps>

Treat the password as visible to anyone who can open the project settings.
Do not reuse a password that protects anything else.

## Common failure patterns

| Symptom | Cause | Fix |
| --- | --- | --- |
| Nothing happens after join | The prompt does not contain `/register`, `/reg`, `/login`, or `/l` as chat text | Check the prompt in the project terminal. The plugin cannot read titles, GUIs, or images. |
| The server says the command is unknown or wrong | The command template does not match the server's syntax | Copy the syntax from the server prompt into the command setting |
| The bot sends the login command at random times | A chat message contains `/l`, for example `/lobby` | Turn the plugin off on that server |
