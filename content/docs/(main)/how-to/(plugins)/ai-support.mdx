SoulFire calls an AI provider through its shared **AI settings**.
The visual **LLM Chat** node, the **AI chat** plugin, and the image-based **Captcha solver** use that connection.
Releases up to 2.10.7 label the plugins **AI Chat Bot** and **Captcha Solver**. Their IDs stay `ai-chat-bot` and `captcha-solver`.
[MCP](/docs/how-to/mcp) works in the other direction: an external assistant calls SoulFire tools.

## Configure the provider

1. Open **AI settings** in the intended project.
2. Set **API Base URL** to the provider's compatible API base.
3. Set **API Key** to a key accepted by that provider.
4. Review **API Request Timeout** and **API Max Retries**.
5. Set a model explicitly in the feature you will use.

The defaults are a 60-second timeout and 5 retries.
A long timeout or many retries can delay the result without correcting a rejected request.
The provider must support the request format used by that feature.
An OpenAI-compatible label does not guarantee support for images or every parameter.

For OpenAI, consult the [API reference](https://developers.openai.com/api/reference/overview) and [model catalog](https://developers.openai.com/api/docs/models/all).
For another provider or local server, use its current compatibility documentation and exact model IDs.
The provider URL must be reachable from the SoulFire server, including inside Docker.

## Verify AI chat

1. Configure the provider first.
2. Open **Plugins** and enable **AI chat**. Then expand **Plugins** and open **AI chat**.
3. Set **AI Model** to a text-capable model that your provider account can use.
4. Set **Keyword** to a trigger such as `!ai`, and set a short **AI System prompt**.
5. Start one bot and send `!ai hello` from a normal Minecraft player.

Expect one reply from the bot. Inspect SoulFire server logs if no reply appears.
The plugin retains a limited per-connection history and limits output for Minecraft chat.
A message containing `<keyword> reset` clears that connection's history.
Use **Filter keyword** if the response must omit the trigger text.

Pause the plugin or stop the bot after the check.
Record the model, latency, and request volume before using it with a fleet.

## Use LLM Chat in a graph

Start with one trigger, **LLM Chat**, and **Log message**. Releases up to 2.10.7 call that node **Print**.
Set a text prompt and the model override, then inspect the returned value.
Connect the result to **Send Chat** only after the value matches the intended behavior.
Use [script debugging](/docs/scripting/debugging) to inspect errors and repeated execution.

A timer, loop, or busy chat trigger can multiply provider requests.
Use rate limits and bounded execution for repeated work.

## Configure Captcha solver

Choose the target server's actual challenge format:

**Captcha Trigger** (`captcha-trigger`) decides what starts the solver:

| Value | Purpose |
| --- | --- |
| `CHAT_MESSAGE` | A chat message triggers an image request |
| `TEXT_BASED` | A regular expression captures a code already present in chat |

**Image Source** (`image-source`) decides where an image challenge comes from:

| Value | Purpose |
| --- | --- |
| `MAP_IN_HAND` | The challenge image comes from a map held by the bot |
| `POV_RENDER` | The challenge image comes from a rendered bot view |

For an image workflow, select a model that accepts image input.
Expand **Plugins** and open **Captcha solver**. Set **Text Trigger**, **Image Source**, **AI System prompt**, and **Response Command** there.
For text capture, use a regular expression with a capture group and the matching response command.
Check the captured value and sent command with one bot on your test target.

An image model cannot correct a missing map or an unusable camera image.
Inspect the captured image first. Use [bot view inspection](/docs/how-to/pov) for camera diagnostics.

## Diagnose the request

| Symptom | Next check |
| --- | --- |
| Authentication or permission error | Provider key, project access, and model availability |
| Model not found | Exact model ID for that provider |
| Timeout or connection error | Network route from the SoulFire server, base URL, and provider status |
| No request occurs | Enabled state, trigger keyword, and graph execution |
| Repeated requests | Trigger frequency, loops, reconnects, and rate limits |
| Unusable response | Prompt, input image, output limits, and model capabilities |

Preserve the provider status and error message, with secrets removed, before changing settings.
