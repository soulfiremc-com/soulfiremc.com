WebDAV is a protocol that shows remote files as a network folder.
The SoulFire server publishes its object storage at the `/webdav/` path.
Object storage holds stored objects such as script code. Each project has a folder named `instance-<project ID>`.

Use WebDAV to read or edit those files without shell access to the SoulFire server.
It is not a server backup. Use [backup and restore](/docs/server/backup-and-restore) for that.

## Before you start

- Start a SoulFire server and connect to it. See [Get started](/docs/start-here) or [Run a SoulFire server](/docs/server).
- Find the server URL that your client uses, such as `https://soulfire.example.com`.
- Use HTTPS for a server on another machine. Over plain HTTP, the token crosses the network unencrypted.

An administrator sees all folders.
Another user sees only the projects where that user has the object storage permission.

## Generate a WebDAV token

Run this command in the SoulFire server console, or in the app **Terminal** as the user who needs access:

```text
generate-token webdav
```

Copy the token. Treat it as a password.
An API token does not work for WebDAV, and a WebDAV token does not work for the API.

## Know your credentials

| Field | Value |
| --- | --- |
| URL | Your server URL followed by `/webdav/`, such as `https://soulfire.example.com/webdav/` |
| Username | Any value. The server ignores it. Your SoulFire username is a good choice. |
| Password | The WebDAV token |

The server reads the token from the password field of HTTP Basic authentication.
A client that sends `Authorization: Bearer <token>` also works.

## Connect on Windows

1. Open File Explorer.
2. Right-click **This PC** and select **Add a network location**.
3. Select **Choose a custom network location**.
4. Enter the WebDAV URL.
5. Enter a username and the WebDAV token as the password.
6. Name the location and finish the wizard.

By default, Windows sends Basic credentials only over HTTPS.
If the connection to an `http://` URL fails, put the server behind [HTTPS](/docs/server/access).

## Connect on macOS

1. Open Finder.
2. Select **Go**, then **Connect to Server**. The shortcut is Command-K.
3. Enter the WebDAV URL and select **Connect**.
4. Enter a username and the WebDAV token as the password.

Finder mounts the share as a volume.

## Connect on Linux

In GNOME Files, open **Other Locations** and enter the URL with the `davs://` scheme, such as `davs://soulfire.example.com/webdav/`.
In KDE Dolphin, enter the URL with the `webdavs://` scheme in the address bar.
Use `dav://` or `webdav://` for a plain HTTP server.

To mount from a terminal, install `davfs2` with your package manager, then run:

```bash
sudo mkdir -p /mnt/soulfire
sudo mount -t davfs https://soulfire.example.com/webdav/ /mnt/soulfire
```

Enter a username and the WebDAV token when `mount` asks for them.

## Check the result

Open the mounted folder.
Expect one `instance-<project ID>` folder for each project that you can access.
To match a folder with a project, copy the project ID from the project's context menu in the app.

## If the connection fails

| Symptom | Next check |
| --- | --- |
| Login prompt repeats | The password must be a token from `generate-token webdav`, not an API token |
| The folder is empty | Your user needs the object storage permission for the project |
| Windows refuses an `http://` URL | Use HTTPS |
| Connection refused or timeout | Open the same host and port that the app uses, with `/webdav/` added |

<Callout type="warn">
  Keep the WebDAV token private. Anyone who has it can read and change the files that your user can access.
  A new token does not cancel an old one. If you expose a token, ask a server administrator to invalidate your sessions.
</Callout>
