The project **Terminal** accepts SoulFire commands.
These commands run on the SoulFire backend. They differ from Minecraft chat commands.
A command without a `bot` selector runs for every bot in the project.

## Send chat through one bot

With `DocsBot_1` connected in your project, run:

```text
bot DocsBot_1 say Hello from one bot
```

Check that only `DocsBot_1` sends the message.

To select more than one bot, separate the account names with commas and put the list in double quotes:

```text
bot "DocsBot_1,DocsBot_2" say Hello from two bots
```

Without the quotes, the command fails at the comma.

## Inspect before changing state

```text
online
bot DocsBot_1 health
```

Check the bot names before you run a movement or inventory command.

## Send a Minecraft command

```text
bot DocsBot_1 say /help
```

The Minecraft server handles `/help` with the bot's permissions.
A SoulFire access token does not grant Minecraft operator permissions.

## Stop movement and bot sessions

```text
bot DocsBot_1 control reset
bots stop
```

`control reset` clears movement inputs. It does not disconnect the bot.
`bots stop` sets every bot in the project to stopped.

<Callout type="warn">
  The plain `stop` command shuts down the whole SoulFire backend. Only admins can run it.
</Callout>

## Look up the available commands

Run `help` in the terminal.
Use [command reference](/docs/reference/commands) for selectors, actions, and task commands.
Plugins can add commands, so `help` on your server shows the complete list.
