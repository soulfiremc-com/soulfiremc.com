## Identify the authentication layer

SoulFire has two separate authentication layers:

- logging a GUI or CLI client into a SoulFire server
- importing and refreshing Minecraft accounts for bots

This page covers bot account imports and Minecraft authentication.
If your GUI cannot log into a SoulFire server, see [Cannot connect or times out](/docs/troubleshooting/cannot-connect-or-times-out#if-the-gui-or-cli-cannot-connect-to-the-soulfire-server).
A SoulFire API token is not a Minecraft account credential.

## Identify the account type first

Before you change anything, identify the account type:

- offline
- Microsoft Java
- Microsoft Bedrock
- cookie-based formats

Then compare your input against [Account formats](/docs/reference/account-formats).
An incorrect input format often causes authentication errors.

## Test without proxies first

If **Use proxies for account auth** is on in **Account Settings**, turn it off and import the same account again.
If the import now works, the proxies cause the error. See [Proxies](/docs/troubleshooting/proxies).
Turn the setting on again only after the import works without it.

## Re-import a minimal sample

If a large batch fails, do not retry the whole batch.

1. Import one account that you know works.
2. Test it without proxies.
3. Join your target server with it.

If one account works, import a small batch before you import all accounts.
Microsoft can rate-limit many logins in a short time. Lower **Account import concurrency** (default 3) if a large batch fails partway.

## If import succeeds but joining still fails

The account works. Check the join instead:

| Symptom | Next step |
| --- | --- |
| `Failed to verify username` | The server is in online mode and needs a Microsoft account, not an offline account |
| A register or login prompt in chat | Configure [Auto login and register](/docs/how-to/auto-register) |
| `Outdated client` or `Outdated server` | Set **Protocol Version** in **Bot Settings** |
| Fails only with proxies | See [Proxies](/docs/troubleshooting/proxies) |

For other kick messages, see [Cannot connect or times out](/docs/troubleshooting/cannot-connect-or-times-out#if-the-minecraft-server-kicks-the-bots).

## What to capture before you report it

- account type
- whether proxies were used for account auth
- whether a single account reproduces the problem
- the exact error text
- whether import fails, refresh fails, or join fails after import

<Callout type="warning">
  Never post raw passwords, cookies, JWTs, or browser-exported secrets in logs or issue reports.
</Callout>
