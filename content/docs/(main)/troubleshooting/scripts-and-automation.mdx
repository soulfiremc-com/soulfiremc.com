## Identify the failed automation layer

Find out which layer runs the failing behavior:

- **visual scripting** in the node editor. Start at the next section.
- **SDK applications**, including `@soulfiremc/beat-game`. See [If an SDK runner looks idle or stuck](#if-an-sdk-runner-looks-idle-or-stuck).

## If a visual script trigger fires but the action does not

Reduce the graph to three parts:

1. The trigger
2. `Log message` (`Print` in releases up to 2.10.7)
3. One action

Then add the other nodes back one at a time.

## Find out whether the trigger provides a bot

Some triggers do not provide a bot.

`On Interval`, `On Script Init`, and `On Script End` do not give you a `bot` automatically.
If your action expects a bot, fetch or loop over bots explicitly.

For the details, see [Scripting](/docs/scripting) and [Triggers](/docs/scripting/triggers).

## Remove timing nodes while isolating

If the graph uses delays or other timing nodes, remove them temporarily.
Make sure that the graph works without them, then add them back one at a time.

## Use `Log message` to trace the graph

Add `Log message` nodes to find out:

- whether the trigger fired
- which branch ran
- whether the expected value exists
- whether the graph stopped before or after the action node

## Keep tick-trigger work small

`On Pre Entity Tick` and `On Post Entity Tick` are not general-purpose places for expensive graphs.
If a graph only works when you simplify it, move the heavy work out of tick timing before assuming the engine is broken.

## If an SDK runner looks idle or stuck

Review the worker before you change SoulFire settings:

1. Make sure that the TypeScript process is still running.
2. Read its latest beat-game event and snapshot.
3. Make sure that the bot is connected and its connection epoch is current.
4. Inspect the active task and control lease.
5. Retry with one bot and an in-memory coordinator.
6. Look for a checkpoint compare-and-set conflict.

If one bot works and a team does not, inspect shared claims, coordinator
membership, and the End-entry quota.

## Choose the correct tool

Visual scripting is for event-driven behavior and custom flows.

If you are trying to implement chat-driven behavior, inventory menus, or custom timed reactions, [Scripting](/docs/scripting) is usually the right layer.
If you are running first-party progression policy, use the
[beat-game runner](/docs/sdk/automation).

## If the issue appeared after an update

Before you change the graph to work around the problem, write down:

- exact SoulFire version
- smallest failing graph
- whether the failure still happens without timing nodes
- whether the failure still happens with one bot

This information makes the error easier to reproduce.

<Callout type="info">
  A minimal graph or SDK action that still fails is more valuable than a
  large workflow that fails for unknown reasons.
</Callout>
