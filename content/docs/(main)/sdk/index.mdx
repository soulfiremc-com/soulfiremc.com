The SoulFire SDK is the official API for Minecraft automation.
Your application controls one bot or a fleet.
SoulFire manages connections, reconnects, permissions, tasks, and plugins.

<Callout type="info">
  The TypeScript SDK is Effect-first and includes a complete Promise facade.
  The Python SDK requires CPython 3.14 and provides native async and sync
  clients.
</Callout>

## How the SDK is organized

```text
SoulFire
├── server metadata and negotiated capabilities
├── administrative services and scoped telemetry
├── plugin catalog and reflective RPC
└── instance(instanceId)
    ├── fleet lifecycle and status streams
    ├── selectors, work distribution, and task groups
    ├── coordinated automation, memory, roles, and claims
    └── bot(botId)
        ├── session and synchronized state
        ├── world, registry, inventory, recipes, and chat
        ├── camera captures, frame streams, and world maps
        ├── typed player actions and path planning
        ├── advanced native protocol access
        └── durable tasks
```

An instance separates permissions and settings.
Each Minecraft account is a separate bot.
SoulFire saves the desired bot state and can reconnect it after the SDK process stops.

## Actions, streams, and tasks

Use an atomic action for one operation, such as sending chat or clicking a slot.
The `sleep` action finishes after the Minecraft server confirms that the bot entered a bed.
The `wake` action leaves the current bed.
Each result has an action ID and a completed, cancelled, or failed state.

Use a stream to observe chat, lifecycle changes, inventory, world state, tasks, or plugins.
Streams support cancellation and backpressure.

Use a durable task for continuous work.
Tasks have stable IDs, progress, resource claims, reconnect policies, typed results, and cancellation.
Combat, following, and survival tasks run near the game loop.

## Compatibility and extensions

Each connection starts with a capability handshake.
The SDK checks the API version, requested features, and required plugin versions.

Plugins can register protobuf RPC services and durable task types. Their
descriptors are discoverable at runtime, so applications can use a published
companion package or call an unfamiliar plugin reflectively.
