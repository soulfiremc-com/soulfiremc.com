The SoulFire SDK is the official programming interface for Minecraft
automation. Your application controls one bot or a fleet while SoulFire owns
the Minecraft connections, reconnect policy, permissions, task execution, and
plugin runtime.

<Callout type="info">
  The TypeScript SDK is Effect-first and includes a complete Promise facade.
  The Python SDK requires CPython 3.14 and provides native async and sync
  clients.
</Callout>

## How the SDK is organized

```text
SoulFire
├── server metadata and negotiated capabilities
├── administrative services and scoped telemetry
├── plugin catalog and reflective RPC
└── instance(instanceId)
    ├── fleet lifecycle and status streams
    ├── selectors, work distribution, and task groups
    ├── coordinated automation, memory, roles, and claims
    └── bot(botId)
        ├── session and synchronized state
        ├── world, registry, inventory, recipes, and chat
        ├── camera captures, frame streams, and world maps
        ├── typed player actions and path planning
        ├── advanced native protocol access
        └── durable tasks
```

An instance is a permission and configuration boundary. Each configured
Minecraft account is an independently controlled bot. Starting a bot persists
the desired state, so SoulFire can reconnect it without keeping the SDK
process alive.

## Actions, streams, and tasks

Use an atomic action for bounded work such as sending chat, clicking one slot,
or interacting with a block. `sleep` is also atomic from the application's
perspective, but it does not complete until the Minecraft server confirms that
the bot entered bed. `wake` leaves the current bed. Action results include a
stable action ID and confirm whether game-thread execution completed,
cancelled, or failed.

Use a stream to observe chat, lifecycle changes, inventory, entities, blocks,
task progress, or plugin events. Streams preserve cancellation and
backpressure.

Use a durable task for continuous work. Tasks have stable IDs, progress,
resource claims, reconnect policies, typed results, and explicit cancellation.
This keeps combat, following, and survival behavior near the game loop instead
of turning every tick into a network round trip.

## Compatibility and extensions

Every connection begins with a capability handshake. The SDK checks the core
API version, requested features, and required plugin versions before returning
a ready client.

Plugins can register protobuf RPC services and durable task types. Their
descriptors are discoverable at runtime, so applications can use a published
companion package or call an unfamiliar plugin reflectively.
