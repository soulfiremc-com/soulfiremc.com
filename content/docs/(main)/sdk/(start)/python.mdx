The Python SDK requires CPython 3.14 or newer.
Use `AsyncSoulFire` for asynchronous services.
Use the synchronous `SoulFire` client for scripts, notebooks, and command-line tools.

## Install

```bash
python -m pip install soulfire
```

## Run a managed local server

`install()` downloads and starts a local SoulFire server. You do not need to provide an API token for this setup.
The client stops the server when the context closes.
The examples create or reuse an instance and an offline bot. Run an offline-mode
Minecraft server at `127.0.0.1:25565` before starting the bot.

<Tabs items={['Async', 'Sync']}>
  <Tab value="Async">
    ```python
    from soulfire import AsyncSoulFire
    from soulfire.common_pb2 import OFFLINE


    async with await AsyncSoulFire.install() as soulfire:
        name = "Hello World"
        existing = next(
            (item for item in await soulfire.instances()
             if item.friendly_name == name),
            None,
        )
        instance = (
            soulfire.instance(existing.id)
            if existing else await soulfire.create_instance(name)
        )

        username = "SoulFireBot"
        bot_id = next(
            (item.profile_id for item in await instance.bots()
             if item.account_name == username),
            None,
        )
        if bot_id is None:
            async for result in instance.login_credentials(OFFLINE, [username]):
                if result.WhichOneof("data") == "one_success":
                    account = result.one_success.account
                    await instance.add_accounts([account])
                    bot_id = account.profile_id
        if bot_id is None:
            raise RuntimeError("Could not create an offline bot")

        bot = instance.bot(bot_id)
        await bot.start()
        await bot.wait_for_online()
        await bot.chat.send("Hello from SoulFire")
    ```
  </Tab>

## Connect to an existing server and send chat

<Tabs items={['Async', 'Sync']}>
  <Tab value="Async">

    import os

    from soulfire import AsyncSoulFire


    async with AsyncSoulFire.connect(
        "https://soulfire.example.com",

## Use structured concurrency

Python 3.14 `TaskGroup` gives fleet operations one cancellation and failure
boundary:

```python
async with asyncio.TaskGroup() as group:
    for bot_id in bot_ids:
        bot = soulfire.instance(instance_id).bot(bot_id)
        group.create_task(bot.chat.send("Ready"))
```

Use `asyncio.timeout()` when a workflow needs one scoped deadline.
Concurrent failures remain available through `ExceptionGroup`.

## Observe synchronized state

<Steps>
  <Step>
    ### Open a session

    ```python
    session = await bot.observe()
    ```
  </Step>
  <Step>
    ### Read state and consume changes

    ```python
    async with session:
        print(session.state.player)

        async for event in session.events():
            print(event)
    ```
  </Step>
</Steps>

The session merges snapshots and deltas, resumes streams when possible, and
requests a new snapshot when continuity is lost.

## Interact with blocks and beds

Use `interact_block` for doors, buttons, beds, redstone controls, and modded
interactive blocks:

```python
await bot.interact_block(
    button_position,
    BLOCK_FACE_NORTH,
)

await bot.sleep(bed_position)
await bot.wake()
```

SoulFire checks that the target block is loaded and reachable. `sleep` waits
for the server-confirmed sleeping state, so an occupied bed or an invalid
sleep attempt fails instead of appearing successful.

## Run durable tasks

```python
task = await bot.tasks.auto_eat(
    ["minecraft:bread", "minecraft:cooked_beef"],
    food_level=14,
    maximum_meals=1,
)

result = await task.result()
print(result.meals_eaten)
```

The same operation is synchronous through `bot.tasks.auto_eat(...)` and
`task.result()`. See [durable tasks](/docs/sdk/tasks) for ownership,
cancellation, and progress.

## Craft and smelt

Production operations live beside recipe discovery:

```python
from soulfire.inventory_pb2 import ItemSelector


recipes = await bot.recipes.list(result_item_id="minecraft:iron_ingot")
task = await bot.recipes.smelt(
    ItemSelector(item_ids=["minecraft:raw_iron"]),
    count=8,
    fuel=ItemSelector(tags=["minecraft:coals"]),
    station=furnace_position,
)
result = await task.result()
```

Use `bot.recipes.craft(recipe_id, ...)` for a recipe returned by `list`.
Inventory-sized recipes need no station. The synchronous client exposes the
same methods without `await`.

## Use generated protocol clients

Generated protobuf messages and ConnectRPC clients remain available as an
advanced escape hatch:

```python
from soulfire.instance_connect import InstanceServiceClient

instances = soulfire.service(InstanceServiceClient)
```

<Callout type="warn">
  Generated clients expose the wire contract directly. Prefer the high-level
  object model when it covers the operation.
</Callout>

Continue with [durable tasks](/docs/sdk/tasks) or
[plugin-defined APIs](/docs/sdk/plugins).
