Use `bot.inventory` to query or move items.
Use a container handle for several operations on the same menu.
The handle includes the latest revision and rejects a stale or replaced menu.

## Select items by ID or tag

Pass an item ID such as `"bread"`, or prefix a tag with `#`, such as `"#logs"`.
IDs without a namespace use `minecraft`.
Counts accept these strings directly. Use `itemSelector` / `item_selector` to build selectors for other inventory and container operations:

```ts
import { itemSelector } from "@soulfiremc/sdk";

const logs = yield* bot.inventory.count("#logs");
yield* chest.deposit(itemSelector("cobblestone"), 64);
yield* chest.withdraw(itemSelector("#foods"), 16);
```

```python
from soulfire import item_selector

logs = yield from bot.inventory.count("#logs")
yield from chest.deposit(item_selector("cobblestone"), 64)
yield from chest.withdraw(item_selector("#foods"), 16)
```

Use a structured selector when you need fingerprints, several IDs, or other advanced filters.

## Open, transfer, and close

<Tabs items={['TypeScript', 'Python']}>
  <Tab value="TypeScript">
    ```ts
    yield* Effect.scoped(
      Effect.gen(function* () {
        const chest = yield* bot.inventory.openScoped(chestPosition);

        yield* chest.deposit(
          { itemIds: ["minecraft:cobblestone"] },
          64,
        );
        yield* chest.withdraw(
          { tags: ["minecraft:foods"] },
          16,
        );
      }),
    );
    ```
  </Tab>
  <Tab value="Python">
    ```python
    chest = yield from bot.inventory.open(chest_position)
    yield from chest.deposit(
        ItemSelector(item_ids=["minecraft:cobblestone"]),
        64,
    )
    yield from chest.withdraw(
        ItemSelector(tags=["minecraft:foods"]),
        16,
    )
    ```
  </Tab>
</Tabs>

`deposit` moves an exact item count from the inventory or hotbar into the container.
`withdraw` moves items in the other direction.
Both methods plan the full transfer before they click any slots.
They stop if the source has too few items or the destination has too little space.

## Click a container button

Use `bot.clickContainerButton(buttonId)` or Python `bot.click_container_button(button_id)` for menu buttons, such as enchanting choices:

```ts
yield* bot.clickContainerButton(0);
```

```python
yield from bot.click_container_button(0)
```

The menu must already be open. Button IDs depend on its type: enchanting options use 0 through 2.
Stonecutter recipes and loom patterns use their positions in the menu list.
A lectern uses 1 for the previous page, 2 for the next page, and 3 to take the book.
The call sends the click without waiting for Minecraft to accept it.
Inspect updated menu state before assuming that the requested operation succeeded.

## Inspect current state

Read `container.snapshot` without another RPC. It contains:

- Container and state IDs
- A stable content revision
- Container type and semantic layout
- Every slot and its inventory area
- Cursor contents
- Selected hotbar slot
- `pathBuildingBlockCount` or `path_building_block_count` for disposable full blocks available to route construction

Call `refresh` after another actor changes the menu.
If a different menu is open, the handle closes and raises `SoulFireContainerClosedError`.

## Choose the best item

SoulFire can rank the bot's tools, melee weapons, armor, food, and safe
scaffold blocks. Every recommendation includes its slot, item snapshot,
total score, and the factors that produced that score.

<Tabs items={['TypeScript', 'Python']}>
  <Tab value="TypeScript">
    ```ts
    const tool = yield* bot.inventory.bestTool(blockPosition, {
      preferHotbar: true,
      preferHighDurability: true,
      preferredEnchantmentIds: ["minecraft:fortune"],
      excludedEnchantmentIds: ["minecraft:vanishing_curse"],
    });

    if (tool !== undefined) {
      yield* Effect.logInfo(tool.factors);
    }
    ```
  </Tab>
  <Tab value="Python">
    ```python
    tool = yield from bot.inventory.best_tool(
        block_position,
        prefer_hotbar=True,
        prefer_high_durability=True,
        preferred_enchantment_ids=["minecraft:fortune"],
        excluded_enchantment_ids=["minecraft:vanishing_curse"],
    )
    ```
  </Tab>
</Tabs>

Tool rankings use the loaded target block and the bot's real mining
calculation. Weapon rankings consider attack damage and speed. Armor rankings
consider defense, toughness, and knockback resistance. Food rankings reject
harmful consumables and compare nutrition with saturation. Scaffold rankings
only include safe, non-falling block items.

Use `rank` when you want several candidates. Enchantment preferences add a
visible score factor, while exclusions remove a candidate entirely. The
response carries the inventory revision so a later mutation can reject stale
input.

## Retry safely

Supply an idempotency key when retrying an operation after an uncertain
network result:

```ts
yield* chest.deposit(selector, 64, {
  idempotencyKey: crypto.randomUUID(),
});
```

The server binds the key to the authenticated user, bot, operation, and
request fingerprint. Reusing it with different input is rejected.
