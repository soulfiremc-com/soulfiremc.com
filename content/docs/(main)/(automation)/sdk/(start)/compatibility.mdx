The examples use SoulFire SDK `%SOULFIRE_SDK_VERSION%`.
The TypeScript SDK requires Effect v4. The Python SDK requires CPython 3.14 or newer and uses effect-py.

## Install the TypeScript SDK

Create an application with Bun:

```bash
mkdir soulfire-tutorial
cd soulfire-tutorial
bun init -y
bun add @soulfiremc/sdk@%SOULFIRE_SDK_VERSION% effect@^4
```

For Node.js 22 or newer, create an ES module project and install the Node runtime too.
The examples use top-level `await`, which needs `"type": "module"`:

```bash
mkdir soulfire-tutorial
cd soulfire-tutorial
npm init -y
npm pkg set type=module
npm install @soulfiremc/sdk@%SOULFIRE_SDK_VERSION% effect@^4 @effect/platform-node@^4
npm install --save-dev tsx
```

Choose the entry point for your application:

| Runtime | Import | Managed local server |
| --- | --- | --- |
| Bun | `@soulfiremc/sdk/bun` | Yes |
| Node.js 22+ | `@soulfiremc/sdk/node` | Yes |
| Browser | `@soulfiremc/sdk/browser` | No |
| Workers, Deno, or custom transport | `@soulfiremc/sdk` | No |

A managed local server means the SDK can download and start SoulFire for you.
The other entry points connect to a SoulFire server that is already running.
See the [TypeScript runtime guide](/docs/sdk/typescript-runtime#provide-an-effect-v4-http-client) to supply your own HTTP client.

Continue with [your first TypeScript program](/docs/sdk/typescript).

## Install the Python SDK

Create a virtual environment with CPython 3.14 or newer:

```bash
mkdir soulfire-python-tutorial
cd soulfire-python-tutorial
python3.14 -m venv .venv
.venv/bin/python -m pip install soulfire==%SOULFIRE_SDK_VERSION%
```

On Windows, use `py -3.14 -m venv .venv` and `.venv\Scripts\python` for the remaining commands.
The SDK also installs `effect-python==0.1.0a2`, which you import as `effect_py`. Do not upgrade it separately.

Continue with [your first Python program](/docs/sdk/python).

## Choose a SoulFire server

For a local script, `SoulFire.createBot` or Python `SoulFire.create_bot` downloads SoulFire and Java when needed.
It creates or reuses the instance and account, starts the bot, and waits for its initial player snapshot.
The tutorials pin the managed SoulFire server with `installation.version` or Python `installation={"version": "%SOULFIRE_SDK_VERSION%"}`.
Without a version, managed installation selects the latest release.

For an existing SoulFire server, use `SoulFire.connect` with its API URL and token.
The handshake checks API versions, capabilities, and required plugins.
Named instance provisioning requires the `instance.provisioning.v1` capability.
See [named setup and existing bots](/docs/sdk/discover-bots).

## Check the installed version

TypeScript:

```bash
bun pm ls
```

Python:

```bash
.venv/bin/python -c "from importlib.metadata import version; print(version('soulfire'))"
```

Expect SDK version `%SOULFIRE_SDK_VERSION%`. A matching version label alone does not prove SoulFire server compatibility.
The SoulFire server must also pass the connection handshake.

## Migrate older applications

The TypeScript high-level API uses Effect operations, streams, and scopes.
Compose calls with `yield*` inside `Effect.gen` and run the complete workflow once at the application boundary.
Use Effect v4 imports such as `effect/http/FetchHttpClient` instead of Effect v3 platform modules.

The Python high-level API uses lazy effects instead of the older async/sync client API.
Compose calls with `yield from` inside `@gen` or `@fn`.
Run the workflow with `run_async(scoped(program).or_die())` at the application boundary.
Stream callbacks return effects; consumers use `run_for_each`, `run_collect`, or other effect-based operations.
Generated protocol clients remain available for direct transport integration.
Read the [TypeScript runtime](/docs/sdk/typescript-runtime) and [Python runtime](/docs/sdk/python-runtime) guides for details.

## Which version each page describes

Different parts of this site follow different SoulFire versions.
Compare the version with your SoulFire server before you copy an example.

| Content | Version | Why |
| --- | --- | --- |
| SDK guides, recipes, and tutorials | `%SOULFIRE_SDK_VERSION%` | The examples are tested against this release |
| [Node reference](/docs/scripting/node-reference) | `%SOULFIRE_SDK_VERSION%` source | Generated from the same revision |
| [HTTP API reference](/docs/openapi) | `2.11.0` | Generated from the development branch, which is ahead of the latest release |
| App labels in the guides | After `2.10.7` | The guides use the updated names. Each page names the earlier label. |
| Plugin template | `2.10.1` | The [first-plugin guide](/docs/development/first-plugin#align-the-template-with-your-soulfire-server) explains how to align it |

A newer SoulFire server can add or rename a field that an older page does not show.
The connected server is the authority for its own commands, nodes, and capabilities.

## Source and generated reference

The documentation uses the [%SOULFIRE_SDK_VERSION% release source](https://github.com/soulfiremc-com/SoulFire/tree/%SOULFIRE_SDK_VERSION%).
The [node reference](/docs/scripting/node-reference) links to that revision.
The [TypeScript API](https://ts.soulfiremc.com/) and [Python API](https://py.soulfiremc.com/) show their SDK version and source.
The [HTTP schema](/docs/openapi) reports its own version and covers unary JSON operations.
The connected SoulFire server's metadata and node palette describe its installed capabilities.

For SDK development, clone the same revision, run `bun install --frozen-lockfile`, and build from `sdk/typescript`.
For a Python source install, use:

```bash
.venv/bin/python -m pip install "soulfire @ git+https://github.com/soulfiremc-com/SoulFire.git@%SOULFIRE_SDK_REVISION%#subdirectory=sdk/python"
```
