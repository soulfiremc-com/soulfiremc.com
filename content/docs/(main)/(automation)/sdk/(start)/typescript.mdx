This program uses the desktop tutorial's instance and account.
It sends one message and stops the bot when its scope closes, including after a workflow error.

## Install the matching SDK

Complete [SDK versions and installation](/docs/sdk/compatibility).
Run the following code from the application directory created by that guide.

## Prepare the backend

1. Connect to a compatible SoulFire server from the desktop app.
2. Create an instance named `Docs tutorial`.
3. Add one account named `DocsBot_1` and set the Minecraft target.
4. Stop that bot before running this program.
5. Run `generate-token api` in the backend console or authenticated terminal.

Use the [first-bot tutorial](/docs/start-here/gui-mode) to prepare the instance.
For a dedicated backend, use [server access](/docs/server/access).
The program finds the instance and bot by their names, so no UUID placeholders remain.

## Set the connection

In the terminal that will run the program, set:

```bash
export SOULFIRE_URL="http://127.0.0.1:38765"
export SOULFIRE_TOKEN="YOUR_API_TOKEN"
```

Use the backend's HTTPS URL for a remote deployment.
`SOULFIRE_URL` is the SoulFire API address, not the Minecraft server address.
Keep the token in your environment rather than the source file.
On PowerShell, use `$env:SOULFIRE_URL = "..."` and `$env:SOULFIRE_TOKEN = "..."`.

## Save the complete program

Create `first-bot.ts`:

```ts title="first-bot.ts" doc-test lineNumbers
import { Effect } from "effect";
import { SoulFire } from "@soulfiremc/sdk";

const baseUrl = process.env.SOULFIRE_URL;
const token = process.env.SOULFIRE_TOKEN;
if (!baseUrl || !token) {
  throw new Error("Set SOULFIRE_URL and SOULFIRE_TOKEN first");
}

const program = Effect.scoped(
  Effect.gen(function* () {
    const client = yield* SoulFire.connect({ baseUrl, token });
    const record = (yield* client.instances()).find(
      (item) => item.friendlyName === "Docs tutorial",
    );
    if (!record) throw new Error("Create the Docs tutorial instance first");
    const instance = client.instance(record.id);
    const account = (yield* instance.bots()).find(
      (item) => item.accountName === "DocsBot_1",
    );
    if (!account) throw new Error("Add the DocsBot_1 account first");
    const bot = instance.bot(account.profileId);

    yield* Effect.addFinalizer(() => bot.stop().pipe(Effect.orDie));
    yield* bot.start();
    yield* bot.waitForOnline();
    yield* bot.chat.send("Hello from the TypeScript tutorial");
    console.log(`Sent chat from ${account.accountName}; stopping the bot`);
  }),
);

await Effect.runPromise(program);
```

## Run and check the result

```bash
bun run first-bot.ts
```

Check three results:

- The program prints `Sent chat from DocsBot_1; stopping the bot`.
- Minecraft chat shows `Hello from the TypeScript tutorial` from that account.
- The bot leaves the Minecraft player list when the program finishes.

A successful connection is separate from a successful Minecraft login.
If login fails, inspect the bot's disconnect reason in **Overview**.
If cleanup cannot reach the backend, stop the bot from the GUI after restoring access.

## Read the code

`SoulFire.connect` returns an Effect that opens an authenticated connection.
`yield*` runs each operation inside `Effect.gen`.
`Effect.scoped` closes the connection and runs the bot-stop finalizer.
`Effect.runPromise` runs the complete program at the application boundary.

Constructing an Effect alone does not send its request.
Do not move the bot out of its connection's scope.
Read [runtime and advanced examples](/docs/sdk/typescript-runtime) for streams, concurrency, managed servers, and platform layers.
