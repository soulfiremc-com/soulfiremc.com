This guide builds a plugin that SoulFire can load.
The official template already contains the required Fabric, Loom, and SoulFire setup.

<Callout type="info">
  The official template repository is [SoulFirePluginExample](https://github.com/soulfiremc-com/SoulFirePluginExample).
  Use it as your starting template. Then compare it with the current [Javadocs](https://ci.codemc.io/job/AlexProgrammerDE/job/SoulFire/javadoc/)
  and current [SoulFire source](https://github.com/soulfiremc-com/SoulFire) for low-level APIs.
</Callout>

If you are new to Fabric itself, keep [Fabric Documentation](https://docs.fabricmc.net/) open too.

## Before you start

- Install Java 25.
- Install Git.
- Use IntelliJ IDEA for Fabric Loom, Mixins, and Java plugin work.
- Have a working SoulFire install where you can test jars in `minecraft/mods`.

## Success criteria

At the end of this guide, you will have:

- a plugin project cloned from the template
- a `ModInitializer` that registers your `ExternalPlugin`
- a built jar in `build/libs`
- a jar that loads from SoulFire's `minecraft/mods` directory

## Align the template with your backend

The template is a starting project, not a promise that its pinned dependencies match your backend.
At this audit, it pins `2.9.1-SNAPSHOT` and Minecraft `1.21.11_unobfuscated`.
The native examples below compile against the [2.10.2 release baseline](/docs/sdk/compatibility), whose runtime uses Minecraft `26.3`.

Compare the template's Minecraft, Fabric Loader, SoulFire, Loom, and Java versions with the backend you will run.
Update the dependency set together. Do not change only the SoulFire version and retain incompatible Minecraft classes.
For a released backend, use its matching published artifacts and source.
For source development, use the matching backend build and local Maven artifacts.

Read [Gradle and project layout](/docs/development/gradle-and-project-layout) before making that change.

## Create the project

<Steps>
  <Step>
    ### Clone the template

    ```bash
    git clone https://github.com/soulfiremc-com/SoulFirePluginExample.git my-soulfire-plugin
    cd my-soulfire-plugin
    ```
  </Step>

  <Step>
    ### Rename the plugin metadata

    Update these files first:

    - `settings.gradle.kts`
    - `build.gradle.kts`
    - `gradle/libs.versions.toml`
    - `src/main/resources/fabric.mod.json`
    - the Java package under `src/main/java`

    Make your plugin ID lowercase and hyphenated.
    Reuse the same ID consistently in `PluginInfo`, `fabric.mod.json`, settings namespaces, mixin config names, and access widener names.
  </Step>

  <Step>
    ### Keep the Fabric entrypoint

    SoulFire plugins are Fabric mods, so the JVM entrypoint is still a normal `ModInitializer`:

    ```java title="Main.java" doc-test
    package com.example.myplugin;

    import com.soulfiremc.server.api.SoulFireAPI;
    import net.fabricmc.api.ModInitializer;

    public final class Main implements ModInitializer {
      @Override
      public void onInitialize() {
        SoulFireAPI.loadPlugin(new MyPlugin());
      }
    }
    ```

    `SoulFireAPI.loadPlugin(...)` registers the plugin with SoulFire.
  </Step>

  <Step>
    ### Implement the plugin class

    For external plugins, extend `ExternalPlugin` and provide `PluginInfo`:

    ```java title="MyPlugin.java" doc-test
    package com.example.myplugin;

    import com.soulfiremc.server.api.ExternalPlugin;
    import com.soulfiremc.server.api.PluginInfo;
    import com.soulfiremc.server.api.event.bot.BotConnectionInitEvent;
    import org.slf4j.Logger;
    import org.slf4j.LoggerFactory;
    import net.lenni0451.lambdaevents.EventHandler;

    public final class MyPlugin extends ExternalPlugin {
      private static final Logger LOGGER = LoggerFactory.getLogger(MyPlugin.class);

      public MyPlugin() {
        super(new PluginInfo(
          "my-plugin",
          "1.0.0",
          "Example SoulFire plugin",
          "YourName",
          "MIT",
          "https://example.com"
        ));
      }

      @EventHandler
      public void onBotInit(BotConnectionInitEvent event) {
        LOGGER.info("Bot {} was initialized", event.connection().accountName());
      }
    }
    ```
  </Step>

  <Step>
    ### Build the jar

    ```bash
    ./gradlew build
    ```

    Your plugin jar will be written to `build/libs/`.
  </Step>

  <Step>
    ### Install it into SoulFire

    Copy the jar into SoulFire's Fabric mods directory and restart SoulFire:

    - all deployments: `minecraft/mods` under the backend's base directory
    - Docker: `/soulfire/data/minecraft/mods` inside the container

    Use [persistent data](/docs/server/data) to locate that directory.
    The remote client's installation directory is not the backend's mod directory.
  </Step>
</Steps>

## Check the event with one bot

Start one bot in a test instance.
Expect the backend log to include `Bot <account name> was initialized`.
This event occurs during initialization, before a usable player and world necessarily exist.
Use a later lifecycle event for actions that need a joined player.

Stop the bot after the check.
If the plugin appears in `plugins` but produces no event output, inspect event registration and the selected instance.

## Add settings and a plugin page

The official example plugin shows the standard pattern:

1. create a `SettingsObject` class with `public static final` properties
2. listen for `InstanceSettingsRegistryInitEvent`
3. call `event.settingsPageRegistry().addPluginPage(...)`
4. read values through `connection.settingsSource()`

That makes your settings appear in the GUI, CLI, and exported instance metadata automatically.

## Make sure that the plugin loaded

Use the built-in plugin inspection tools:

- open the instance UI and view **Plugins**
- run `plugins` in the terminal
- run `print-docs plugins` if you want the current built-in plugin documentation output

If the mod failed before registration, read the startup logs first.
Fabric loading problems, missing dependencies, and bad mixin config usually fail before SoulFire ever sees your `ExternalPlugin`.

If Fabric itself is complaining, go back to:

- [Gradle And Project Layout](/docs/development/gradle-and-project-layout)
- [Fabric Documentation](https://docs.fabricmc.net/)
