## The short version

| If you want to... | Start with... | Why |
| --- | --- | --- |
| Learn SoulFire with the least setup | [GUI Mode](/docs/start-here/gui-mode) | Requires the fewest setup steps |
| Keep bots running on a VPS or shared machine | [Dedicated Server](/docs/start-here/dedicated-server) | Keeps the backend running even when the GUI is closed |
| Automate from a terminal or use a system without a desktop | [CLI Mode](/docs/start-here/cli-mode) | Works well for scripts and SSH sessions |
| Share one backend with multiple users or clients | [Dedicated Server](/docs/start-here/dedicated-server) | GUI and CLI clients can connect to the same remote server |

## What each part means

### GUI client

The GUI is the desktop app.
Use it to create instances, change settings, view bot state, and manage plugins or scripts.

### CLI client

The CLI is the terminal client.
Use it for automation, SSH sessions, or systems without a desktop.

### Integrated server

The GUI and CLI include a SoulFire server.
You can run bots on your computer without a separate server.

### Dedicated server

A dedicated server runs SoulFire separately, usually on another computer.
GUI and CLI clients connect to it over the network.

## Recommended paths

### New user

1. [Install SoulFire](/docs/start-here)
2. [Run your first bots in GUI mode](/docs/start-here/gui-mode)
3. Use [How-to Guides](/docs/how-to) for accounts, proxies, plugins, and integrations

### Remote operator

1. [Deploy a dedicated server](/docs/start-here/dedicated-server)
2. Connect from the GUI with the server URL and access token
3. Use [How-to Guides](/docs/how-to) for ongoing administration tasks

### Automation user

1. Decide whether the CLI will use a local or remote server
2. Read [CLI Mode](/docs/start-here/cli-mode)
3. Read [Automation](/docs/automation) and choose an automation method
4. Keep [CLI Flags](/docs/reference/cli-flags) open as your reference
