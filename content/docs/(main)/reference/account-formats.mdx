## Supported account types

In the app, select **Add accounts** on the **Accounts** page.
The menu lists these types under **Java Edition** and **Bedrock Edition** with shorter names, for example **Microsoft credentials**.

| Type | CLI value | What you provide | Notes |
| --- | --- | --- | --- |
| **Microsoft Java Credentials** | `MICROSOFT_JAVA_CREDENTIALS` | `email:password` | The account must own Minecraft Java Edition |
| **Microsoft Java Device Code** | `MICROSOFT_JAVA_DEVICE_CODE` | Browser sign-in | Good when you do not want to paste credentials |
| **Microsoft Bedrock Credentials** | `MICROSOFT_BEDROCK_CREDENTIALS` | `email:password` | Bedrock login with email and password |
| **Microsoft Bedrock Device Code** | `MICROSOFT_BEDROCK_DEVICE_CODE` | Browser sign-in | Browser-based Bedrock login |
| **Microsoft Java Refresh Token** | `MICROSOFT_JAVA_REFRESH_TOKEN` | One refresh token per line | Suitable for long-lived imports |
| **Microsoft Java Cookies** | `MICROSOFT_JAVA_COOKIES` | Exported `login.live.com` cookies | SoulFire exchanges them for a refreshable auth chain |
| **Microsoft Java Access Token** | `MICROSOFT_JAVA_ACCESS_TOKEN` | Raw Minecraft access token | Short-lived and cannot be refreshed |
| **Offline** | `OFFLINE` | One username per line | Only works on servers that accept offline accounts |

### CLI values [#cli-values]

Pass the **CLI value** to `--account-type`, for example `--account-type OFFLINE`.
The CLI also accepts `THE_ALTENING` for TheAltening tokens.

## Import formats

### Microsoft Java Credentials

The account must own Minecraft Java Edition.

```text
email:password
email2:password2
email3:password3
```

### Microsoft Java Device Code

Start the import from SoulFire and complete the device-code login in your browser when prompted.

### Microsoft Bedrock Credentials

This is the credential-based option for Bedrock Edition servers.
The account needs Xbox Live enabled and a gamer tag.

```text
email:password
email2:password2
email3:password3
```

### Microsoft Bedrock Device Code

Start the import from SoulFire and complete the device-code login in your browser when prompted.

### Microsoft Java Refresh Token

Use this format when another tool or provider gives you refresh tokens.

```text
refresh_token_here
refresh_token_here2
refresh_token_here3
```

### Microsoft Java Cookies

SoulFire accepts these cookie formats from `login.live.com`:

- **Netscape cookie jar**: tab-separated cookie exports from browsers or curl
- **Cookie Editor JSON**: an array of cookie objects from the Cookie Editor browser extension
- **Raw cookie header**: semicolon-separated `name=value` pairs

SoulFire exchanges these cookies for tokens that it can refresh.

### Microsoft Java Access Token

Use this when you only have the raw Minecraft access token.

```text
eyJhbGciOiJIUzI1NiJ9...
```

Access-token imports cannot be refreshed. When the token expires, you need to import a new one.

### Offline

Offline usernames are generally case-sensitive. That means `username` and `UserName` are treated as different accounts.
Some authentication plugins, such as AuthMe, can reject names that differ only by case.

```text
Username
Username2
Username3
```

## Account settings reference

| Setting | Default | What it does |
| --- | --- | --- |
| **Shuffle accounts** | `false` | Randomizes account order before bots join |
| **Use proxies for account auth** | `false` | Sends Microsoft authentication through your configured proxies |
| **Account import concurrency** | `3` | Controls how many account imports run at the same time |

## Offline generation in the client

The generation dialog takes an amount, a name format containing `%d`, and a duplicate-handling mode.
These are client inputs, separate from the server's account settings.
For example, an amount of `2` with `DocsBot_%d` creates `DocsBot_1` and `DocsBot_2`.

See [add accounts](/docs/how-to/import-accounts) for the workflow.
If an import or login fails, see [Accounts and authentication](/docs/troubleshooting/accounts-and-authentication).
