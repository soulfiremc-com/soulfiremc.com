The updated app uses **Project** for a saved automation container. Older releases call it **Instance**.
A project owns bots, settings, accounts, proxies, scripts, files, access, and metadata, and remains available while its bots are stopped.
**Fleet** describes a selection of bots within that project.

The display-name migration changes labels, not API identities, data ownership, configuration formats, or runtime behavior.
Published SDK references and generated node documentation keep their pinned source revision and can use the earlier labels.

## Product names

| Earlier label | Updated label | Compatibility |
| --- | --- | --- |
| Instance | Project | API types and fields keep `Instance`, `instanceId`, and `instance_id`. |
| Instance settings | Project settings | Existing routes stay valid. |
| Bot POV | Bot view | POV remains the technical capability name. |
| Control lease in app text | Take control / Release control | Lease terminology remains in the API. |
| Load profile / Save profile | Import configuration / Export configuration | Existing JSON files remain importable. |
| Duplicate instance | Create from configuration | Same copy operation, with its contents described explicitly. |

A **Minecraft profile ID** still identifies a Minecraft account. It is not a configuration file or a Soulfire user ID.
The `instance` CLI command and SDK methods such as `client.instance(...)`, `getOrCreateInstance`, and `get_or_create_instance` remain valid.
Raw API errors can still refer to an Instance or an `instance_id` field.

| Fake Virtual Host | Handshake host override | `fake-virtual-host` |
| Server List Bypass | Ping before join | `server-list-bypass` |

Other built-in names use sentence case, including Auto eat, Auto respawn, Auto reconnect, Captcha solver, Chat logger, Disconnect logger, and Client brand.
Anti AFK retains its familiar acronym.
The migrated app searches stable IDs in hyphenated, spaced, and compact forms, so earlier names remain discoverable.
A connected server supplies its feature labels. Older servers can still show the earlier names.

## Configuration copies and exports

**Create from configuration** copies settings, accounts and their credentials, proxies, project and account persistent metadata, and the icon.
It excludes scripts, files, permissions, and history. The new project belongs to the person who creates it.

**Export configuration** includes settings, accounts and their credentials, proxies, and account persistent metadata.
The app currently omits project-level persistent metadata from exports.

<Callout type="warn" title="Keep exported files private">
  Configuration files contain account credentials and proxy passwords. Share them only with people who should have those credentials.
</Callout>
A configuration export is not a complete project backup.

New downloads use `soulfire-configuration.json`. Older files named `profile.json` remain importable.
Use [server backup and restore](/docs/server/backup-and-restore) when you need to recover the complete Soulfire server.

## Versions and translations

The app's English source strings change first. Other locales keep their existing names until their Crowdin translations are reviewed.
Examples that use `instance` identifiers remain compatible, including examples for SDK versions published before this display-name migration.

The [shared naming proposal](https://github.com/soulfiremc-com/brand/pull/1)
records the selected mappings and the coordinated rollout. Its acceptance status is separate from implementation and release.
