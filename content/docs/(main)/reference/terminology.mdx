## Server and client

SoulFire has two main parts: a server and a client.

### Server

The docs call it the **SoulFire server** to keep it apart from the Minecraft server that bots join. Some logs and older pages call it the **backend**.
It manages users, bots, and projects.

- **Users**: The server manages the users and their permissions.
- **Projects**: A project keeps one group of accounts, bots, proxies, scripts, settings, and permissions separate from other groups.
- **Bots**: Each configured account is one independently controlled bot with its own desired and runtime state.
- **Plugins**: The server loads and manages SoulFire plugins.
- **Proxies/Accounts**: The server manages the proxies and accounts used by the bots.

### Client

The client is also called the **frontend**.
It connects to a SoulFire server and sends requests to manage users, projects, bots, plugins, proxies, and accounts.

- **GUI**: the desktop app.
- **CLI**: the terminal client.
- **API client**: your own software that uses the SoulFire API or an SDK.

A client can connect to any SoulFire server if it has valid credentials and a compatible API version.

## Product names and API names

The app calls the saved automation container a **Project**. A **Fleet** is a selection of its bots.
The API and SDKs keep `Instance`, `instance_id`, `instanceId`, and `client.instance(...)` for compatibility.
A Minecraft profile ID still identifies a Minecraft account.

See [names and compatibility](/docs/reference/naming) for old labels, feature names, variable lifetimes, and configuration contents.
