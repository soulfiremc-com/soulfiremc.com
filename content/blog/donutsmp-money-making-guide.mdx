## The short answer

DonutSMP's economy has two currencies and four main loops: AFK shards, spawner farms, selling to the server with a sell multiplier, and player trading through orders and the auction house. If you run a server with a similar economy, each loop is a place where automated players can create too much money or too much lag.

This post explains the loops, then shows how to test them on your own server with [SoulFire](/download) bots before real players find the weak spots.

<Callout type="warning">
**Do not run bots on DonutSMP.** Its rules ban scripts, macros, and auto-clickers, and staff ban associated accounts together. Everything in this post is for a server that you own or have permission to test.
</Callout>

## How DonutSMP's economy works

DonutSMP changes prices and rates often. The [DonutSMP Wiki](https://donutsmp.fandom.com/wiki/Sell_Multiplier) and the server's own `/shop` show the current values.

### Currencies

| Currency | How players earn it | What it buys |
|----------|---------------------|--------------|
| **Money** | `/sell`, auction house sales, filling `/order` listings | Items on `/ah`, player trades |
| **Shards** | Time in the AFK zone, kills, and some store perks | Spawners and crates in `/shop` |

### Trading systems

| System | Command | What it does |
|--------|---------|--------------|
| **Auction house** | `/ah` | Players list and buy single items |
| **Orders** | `/order` | Players post bulk buy requests that others fill |
| **Direct sell** | `/sell` | The server buys items at fixed prices, scaled by the seller's multiplier |

### The sell multiplier

Each player's sell multiplier grows with their total sales, up to 3x. A player at a high multiplier can buy items from other players through `/order` and sell them to the server for more than they paid. Order supply limits how far this scales.

## Where an economy like this breaks

Each loop has a failure mode that only shows up with many players, or with players who automate.

- **AFK rewards create money from nothing.** The total grows with every account that stays online. Bots or alt accounts multiply it.
- **Spawner farms keep chunks loaded.** A player who stands next to a farm keeps it running, so each farm adds to the tick time all day.
- **The sell multiplier enables arbitrage.** If an item's sell price times the multiplier is higher than what players accept for it in an order, buying and selling it creates money with no work.
- **The auction house rewards speed.** A script that polls `/ah` can buy underpriced listings before any human, and the command itself costs server time.

## Test each loop with bots

Run these tests on a copy of your server with the same economy plugins. SoulFire bots run Minecraft client code, so they use your commands and GUIs the same way a player does. The [testing guide](/docs/testing) covers how to prepare a run and record results.

<Steps>
<Step>

### AFK reward rate

Connect 10 bots and send them to the AFK area with an **On player ready** trigger and a **Send Chat** node that runs your AFK command. After one hour, compare each bot's balance with your configured rate. Then check whether your AFK plugin limits rewards per IP address, because all bots from one machine share one address.

</Step>
<Step>

### Farm and chunk load

Place bots next to a test spawner farm, and run a [Spark](https://spark.lucko.me/) profile with no bots, then with 10, then with 50. If entity ticking grows faster than the bot count, lower the farm's stack size or spawn rate. The [stress testing guide](/blog/stress-testing-minecraft-servers) explains how to read the profile.

</Step>
<Step>

### Sell multiplier arbitrage

Give a test account the maximum multiplier. Post an order for a cheap item, fill it from a second account, and `/sell` the delivery. If the loop ends with more money than it started with, set a minimum order price or exclude ordered items from the multiplier.

</Step>
<Step>

### Command rate limits

Run a script that sends `/ah` or `/sell` from 20 bots on an **On Interval** trigger every few seconds. Watch TPS and the plugin's cooldown messages. A plugin without a per-player cooldown lets one script slow the whole server.

</Step>
</Steps>

## Build the test scripts

SoulFire's [visual scripting](/docs/scripting) connects nodes into a graph, so you can build these tests without code. Releases before 2.10.8 show **On Join** for **On player ready** and **Pathfind To** for **Go to position**.

| Test | Nodes |
|------|-------|
| Run commands | **Send Chat** |
| Read confirmations | **On Chat**, **String Contains**, **Regex Match** |
| Use shop GUIs | **On Container Open**, **Click Slot**, **Close Inventory** |
| Move to a farm | **Go to position**, **Get Position** |
| Repeat on a timer | **On Interval**, **Rate Limit** |
| Record balances | **Set persistent bot variable**, **Discord Webhook** |

A script that checks the AFK reward rate looks like this:

```text
On player ready
  → Wait (3s)
  → Send Chat ("/afk")

On Interval (every 10 min)
  → Send Chat ("/balance")

On Chat
  → Regex Match (balance line)
  → Set persistent bot variable ("balance")
  → Discord Webhook (bot name and balance)
```

The [script examples](/docs/scripting/examples) have starter graphs for chat commands, timers, and Discord alerts that you can adapt.
